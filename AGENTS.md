# AGENTS.md

Guidance for AI coding agents working in this repository.

## Project overview

**read4me** is a small Expo / React Native app that reads documents aloud with text-to-speech. The user picks a `.txt` or `.json` file, the app splits it into segments, and `expo-speech` speaks them one at a time while the screen shows the current segment (text, an image, or syntax-highlighted code).

- Expo SDK 55, React Native 0.83 (New Architecture only; the legacy architecture no longer exists), React 19.2, TypeScript (strict)
- Routing: `expo-router` (file-based, typed routes); React Compiler experiment on
- UI: `native-base` plus plain `StyleSheet`; icons from `@expo/vector-icons`
- Native modules: `expo-speech`, `expo-file-system`, `@react-native-documents/picker`, `@react-native-community/slider`, `react-native-gesture-handler` + `react-native-reanimated` (image zoom viewer; the root is wrapped in `GestureHandlerRootView`). Prefer Expo modules or libraries with New Architecture support; avoid old bridge-only modules
- **Android-first**: the main screen uses `DrawerLayoutAndroid`, so iOS and web do not work as-is. Android package: `com.duchunter.read4me`.

## Commands

The repo uses **yarn** (`yarn.lock`).

```bash
yarn install          # install dependencies
yarn android          # expo run:android – native build + run (needs Android SDK/emulator or device)
yarn start            # expo start – Metro dev server
yarn lint             # expo lint (ESLint flat config, eslint-config-expo)
npx tsc --noEmit      # type-check
yarn prebuild         # expo prebuild – regenerate native projects
```

Expo Go cannot run this app because it relies on custom native modules (document picker, slider). Use a development build (`yarn android`).

There is no test suite. Verify changes with `yarn lint` and `npx tsc --noEmit`, and by running the app on Android when behavior changes.

## Layout

```
app/
  _layout.tsx        Root: NativeBaseProvider + headerless Stack
  index.tsx          The only screen: file picking, TTS playback state, drawer, rendering
components/          Presentational components (HeaderBar, DrawerContent, PlayControl,
                     SeekBar, TextContent, ImgContent, ImageViewer, CodeContent)
config/
  color.ts           Color palette (DARK_PRIMARY, DARK_SECONDARY, BLUE_PRIMARY)
  constants.ts       Screen size, IS_IOS, DOC_MODE list
utils/transformer/   File content -> segment array (one transformer per document mode)
assets/images/       App icon, splash, adaptive icon layers
docs/                User docs; json-format.md specifies the MEDIUM_POST JSON format (keep it in sync
                     with transformMediumPost's validation and the rendering in app/index.tsx)
```

`android/` and `ios/` are generated by `expo prebuild` (Continuous Native Generation) and are gitignored. Don't commit them.

## How it works

- **Segments.** A document becomes an array of `{ text?: string; img?: string; files?: { filename, language, content }[] }`. `app/index.tsx` prepends an empty segment, then steps through the array with `currentIndex`.
- **Playback loop.** `speak()` speaks `data[currentIndex]` with `Speech.speak`. Its `onDone` callback increments `currentIndex`, and an effect calls `speak()` again while `isPlaying` is true. `Speech.stop()` does not fire `onDone`, so skipping and pausing stop the current segment without advancing. Image segments say "We have a picture" and code segments say "We have some code" while the matching view is shown, then playback pauses on that segment (`mediaPauseIndexRef` records it) so the user can look; pressing Play moves on to the next segment.
- **Controls.** `PlayControl` handles play/pause, skipping ±5 segments, speed (a rate multiplier kept in `rateRef`, 1 = normal, applied from the next segment) and play mode (0 = repeat, 1 = repeat one, 2 = stop at end). `SeekBar` jumps to a given index.
- **Document modes** (`DOC_MODE` in `config/constants.ts`, chosen from the drawer):
  - `TEXT` → `transformTextFile`: joins lines, then splits on `". "` into sentences.
  - `MEDIUM_POST` → `transformMediumPost`: parses JSON and returns its `content` array, which must already hold segments in the shape above. It validates every segment and rejects the whole file on the first bad one. The format is documented in `docs/json-format.md`.

### Adding a document mode

1. Add `utils/transformer/transformX.ts` that returns a segment array (on invalid input, alert and return `[{}]` as the existing transformers do), and export it from `utils/transformer/index.ts`.
2. Add the mode key to `DOC_MODE` in `config/constants.ts`. The drawer turns the key into a label (`MEDIUM_POST` → "Medium post").
3. Add a `case` to the `switch (docMode)` in `pickFile` in `app/index.tsx`. Also update the file extension check there if the mode reads a new file type.

## Conventions

- TypeScript with `strict: true`. Import with the `@/` alias (maps to the repo root), e.g. `@/components/HeaderBar`, `@/config/color`.
- Function components typed as `React.FC<Props>` with a `Props` interface, a default export, and a `StyleSheet.create` block at the bottom of the file.
- Take colors from `config/color.ts` instead of hard-coding them. The UI is dark-themed.
- Double quotes and semicolons in components; VS Code formats on save and organizes imports.
- Untyped libraries are imported with `// @ts-ignore` (see `CodeContent.tsx`). Keep that pattern rather than adding loose `declare module` shims.
- Commit messages are short and imperative, sometimes with a conventional prefix (`refactor: ...`).

## Notes

- Native config changes (permissions, package name, splash, plugins) go in `app.json` or a config plugin, never in hand edits to `android/`. Run `yarn prebuild --clean` to regenerate after changing them.
- Navigation goes through `expo-router`. Don't add direct `@react-navigation/*` stacks or navigators.
- Don't commit signing material (`*.jks`, `*.p12`, `*.key`, etc.). These are already gitignored.
